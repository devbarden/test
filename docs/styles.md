# Стили

Как устроен CSS: где что лежит, почему именно так и какие правила проверяет
`npm run lint:styles` (`scripts/check-styles.ts`). Оформление комментариев —
в `CLAUDE.md`.

## Карта

```
src/styles/                 глобальное, подключается одним <link> в <head>
  index.css                 порядок слоёв + @import остальных файлов
  fonts.css                 @font-face (вне слоёв)
  reset.css                 @layer reset      — обнуление браузерных стилей
  tokens.css                @layer tokens     — палитра, роли, шкалы
  base.css                  @layer base       — body, фокус, иконки, reduced motion
  view-transitions.css      @layer base       — переходы между страницами
  utilities.css             @layer utilities  — .visually-hidden
  clerk.css                 вне слоёв — наше кольцо фокуса на контролах Clerk

src/components/ui/**        *.module.css  →  @layer ui
src/components/**           *.module.css  →  @layer components
src/features/**             *.module.css  →  @layer features
src/screens/**              *.module.css  →  @layer screens
```

## Каскадные слои

Первая строка `index.css` фиксирует порядок для всего документа:

```css
@layer reset, tokens, base, ui, components, features, screens, utilities;
```

Каждый модуль целиком лежит в одном блоке `@layer <слой папки> { … }`.
Слои повторяют направление импортов (`screens → features → components`),
поэтому `className`, переданный сверху, **всегда** побеждает собственные
стили компонента — независимо от специфичности и от того, в каком порядке
загрузились чанки. Раньше это держалось на удаче: `.pill.xs` (0,2,0) у
кнопки перебивал бы `.foo` (0,1,0) экрана, а `auth-screen` писал
`.topBar .mobileBrand`, только чтобы пересилить `display: flex` из
`HomeLink`.

Стили Clerk внедряются без слоя и стоят выше всех наших — его форма
выглядит так, как её настроил `clerk-appearance.ts`, а не наш reset.
Единственное исключение — `clerk.css`: тоже без слоя, чтобы кольцо фокуса
на контролах Clerk было таким же, как во всём приложении.

## Модуль компонента

```css
@layer ui {
	.root {
		--_height: auto;              /* приватные свойства — с дефолтом на .root */
		--icon-size: var(--icon-md);  /* размер иконок внутри */

		display: inline-flex;
		min-block-size: var(--_height);
		font: var(--type-body-md);

		&:hover { … }                 /* состояния — вложенностью */
		&:disabled { … }

		@media (width < 40rem) { … }  /* адаптив — рядом с правилом, которое меняет */
	}

	.lg {                           /* вариант задаёт значения, а не свойства */
		--_height: var(--control-height-lg);
	}

	.label { … }                    /* части — плоские классы */
}
```

- **Один модуль — один компонент**, лежит рядом с ним и импортируется как
  `styles` только файлами той же папки. Семейство компонентов может делить
  модуль (`field` + `input` + `text-area`, `section` + `section-card`), но
  чужой модуль не импортирует никто — только компонент.
- **`.root` — внешний элемент компонента.** Части называются по роли в
  camelCase (`.cardTitle`, `.formColumn`), варианты — по значению пропа
  (`.primary`, `.lg`, `.muted`).
- **Варианты в TSX — явной картой**, а не `styles[variant]`:

  ```ts
  const TONE_CLASS = {
  	muted: styles.muted,
  	raised: styles.raised,
  	success: styles.success,
  } satisfies Record<PanelTone, string | undefined>
  ```

  `satisfies` заставляет добавить класс при новом значении пропа, а линтер
  проверяет, что каждый `styles.x` существует и каждый класс модуля кем-то
  прочитан.
- **Состояние берётся из DOM**, если оно там уже есть: `:disabled`,
  `[aria-invalid="true"]`, `[aria-current]`, `[open]`, `:has(input:checked)`.
  Отдельный класс вроде `.checked` дублировал бы то, что уже знает
  разметка, и мог бы с ней разойтись.
- **Вложенность** — только для состояний, псевдоэлементов, модификаторов
  части (`&.done`), контекста (`.ink &`) и медиазапросов. Структуру DOM
  вложенностью не повторяем: части остаются плоскими классами. Сборка
  разворачивает вложенность для браузеров из `build.target`.
- **Приватные свойства** `--_имя` — внутренний API компонента: вариант
  меняет значение, а `.root` — единственное место, где оно превращается в
  CSS. Все они объявлены на `.root`, поэтому одноимённое свойство предка не
  протекает внутрь.
- **Родитель расставляет, компонент выглядит.** Отступы снаружи
  (`margin`), ширину в сетке и позицию задаёт тот, кто рендерит компонент,
  через `className`. Внутренний вид меняется новым вариантом в самом
  компоненте, а не переопределением снаружи.

## Токены

`tokens.css` — единственное место с сырыми значениями.

| Группа     | Пример                                   | Правило                                   |
| ---------- | ---------------------------------------- | ----------------------------------------- |
| Цвет       | `--color-text-secondary`                 | только роли; палитра и литералы — ошибка  |
| Типографика| `font: var(--type-body-sm)`              | размер + интерлиньяж + вес + гарнитура    |
| Отступы    | `--space-4`, `--space-3-5`               | шаг 0.25rem                               |
| Прочее     | `--radius-*`, `--shadow-*`, `--z-*`, `--duration-*` | `z-index` — только из шкалы     |

Типографика — шорткаты для свойства `font`, поэтому размер никогда не
расходится со своим интерлиньяжем. Другой вес — отдельной строкой после
шортката: `font: var(--type-body-sm); font-weight: var(--weight-medium);`.
`body` — интерфейсный текст, `prose` — абзацы для чтения, `display` —
заголовки и крупные цифры.

## Иконки

Любая иконка Lucide берёт размер из `--icon-size` (`base.css`). Компонент
задаёт его на своём корне или на классе самой иконки — вместо
`.x svg { inline-size; block-size }`. `Spinner` читает то же свойство,
поэтому внутри кнопки он того же размера, что и её иконки.

## Брейкпоинты

Медиазапросы не читают `var()`, поэтому набор фиксирован и проверяется
линтером: `30rem`, `40rem`, `48rem`, `60rem`, `64rem`, только в range-синтаксисе
и только в двух формах — `(width < x)` и `(width >= x)`, так что две стороны
одного брейкпоинта не перекрываются и не оставляют щели в 1px. В `rem`
брейкпоинты следуют за размером шрифта, который выбрал читатель.
`lib/breakpoints.ts` — копия единственного брейкпоинта, нужного скрипту.

## Что проверяет `lint:styles`

- модуль целиком в `@layer` своей папки, `index.css` объявляет порядок;
- нет цветовых литералов и `--palette-*` вне `tokens.css`;
- медиазапросы — только из набора брейкпоинтов, без `min-/max-width`;
- модуль импортируется как `styles` из своей папки, без `styles[…]`;
  каждый `styles.x` определён, каждый класс прочитан, имена в camelCase;
- `z-index` — из шкалы `--z-*`, `!important` — только в `src/styles`.
